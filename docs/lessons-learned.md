# Lessons Learned

Factory process retrospectives. Each entry documents a real deviation observed during a run.

## LL-001 — Bootstrap must not implement feature tasks

**Observed in:** PR #1 (`ui.dashboard.shell`), run record `.factory/runs/2026-05-28-ui-dashboard-shell/`
**Date:** 2026-05-30
**Severity:** High — invalidates task traceability

### What happened

The bootstrap step committed the full dashboard shell implementation (`src/features/dashboard/`, `src/app/dashboard/`, `src/lib/mock-data.ts`) directly onto `main` in commit `4948faf`. These files were within the scope of the pending task `ui.dashboard.shell`.

When the task worker cut a branch and opened a PR, the actual PR diff contained only Factory infrastructure files. The feature code was already on `main`. The PR could not serve as the traceable delivery artifact for the task.

### Why it matters

- Task traceability is broken: there is no PR that shows *when* and *how* the feature was delivered.
- The run record was incorrect: it listed files as PR changes that were not in the PR diff.
- The Factory's core loop (task → branch → PR → CI → merge) was bypassed for the most visible first task.

### Root cause

The bootstrap worker conflated "scaffold the repo so it compiles and has a visible starting point" with "implement the first feature". These are separate responsibilities:

- **Bootstrap scope:** Next.js scaffold, `.factory/` structure, `package.json` scripts, CI workflow, README.
- **Task scope:** everything under `src/features/**`, `src/app/dashboard/**`, `src/lib/mock-data.ts`, and any application-level `src/app/page.tsx` changes beyond the bare scaffold.

### Rule

> **Bootstrap workers must not implement feature tasks on `main`.**
>
> The bootstrap commit may include:
> - The bare framework scaffold (as generated by `create-next-app` or equivalent)
> - `.factory/` structure and policy files
> - `package.json` script additions required for CI
> - CI workflow files
> - `README.md`
>
> The bootstrap commit must NOT include:
> - Any file listed as `allowed_files` in a pending task spec
> - Application components, pages, layouts, or data files
> - Any code that belongs to a defined task in the task graph

### Corrective action

For this prototype, the feature code is already on `main` and the PR has been reviewed. No rollback is warranted. The run record has been corrected (audit correction PR: `factory/task/audit-correction-pr1`) to reflect the actual PR diff and document the deviation.

For all future products: enforce this rule at bootstrap review time.

## LL-002 — Infra changes must not be bundled into UI task branches

**Observed in:** PR #1 (`ui.dashboard.shell`), commits `076fc27` and `dbc310b`
**Date:** 2026-05-30
**Severity:** Medium — policy violation, blocked auto-merge

### What happened

The task spec for `ui.dashboard.shell` blocks `.github/**`. During the task run, `.github/workflows/factory-validation.yml` was created and subsequently patched on the task branch to fix a CI regression (`next lint` removed in Next.js 16).

This made the PR ineligible for auto-merge and introduced an infra change into a UI task's audit trail.

### Root cause

The CI workflow bug was only discovered when validation was run as part of the task. The worker fixed it inline rather than stopping and creating a separate infra task.

### Rule

> **When a blocked file requires a change to make a task's required checks pass, stop and escalate.**
>
> Create a separate infra task for the blocked-file change. The UI task should be paused (status: `blocked`) with a dependency on the infra task.
>
> Do not cherry-pick infra fixes onto feature task branches. Do not bundle `.github/**`, `package.json`, or `.env` changes into UI/feature PRs.

### Corrective action

The workflow fix is correct and necessary. It should be extracted to a dedicated infra task in the next run cycle (suggested task id: `infra.ci.fix-lint-script`).

## LL-003 — Run records must reflect actual PR diff, not intended diff

**Observed in:** PR #1 (`ui.dashboard.shell`) original run record
**Date:** 2026-05-30
**Severity:** Medium — audit record inaccurate

### What happened

The original run record listed 6 `src/**` files as "Files Changed" in the PR. These files were not in the actual PR diff — they existed on `main` from the bootstrap. The discrepancy was caught by the internal review and a Codex automated review comment.

### Rule

> **Run records must list only files that appear in `git diff main...branch --name-only`.**
>
> Run records are audit artifacts. They must reflect what was actually delivered in the PR, not what the worker intended to deliver or what exists in the codebase.
>
> Before writing the "Files Changed" section, always verify with: `git diff <base>...<branch> --stat`

### Corrective action

Run record corrected in audit correction PR (`factory/task/audit-correction-pr1`).
